# Empty State Patterns

Empty states appear when there is no content to display. A good empty state explains why the area is empty and offers a clear next action. Compose them using layout primitives (`Box`, `Stack`) for structure, `Heading` and `Paragraph` for messaging, and `Button` for the primary action.

## Anatomy

Every empty state should include:

1. **Visual** (optional) -- An illustration or icon to set context.
2. **Heading** -- A short title explaining the state.
3. **Description** -- One or two sentences with guidance.
4. **Action** (when applicable) -- A button to resolve the empty state.

## Empty Search Results

When a search or filter returns no matches:

```jsx
import { Box, Stack, Heading, Paragraph, Button } from '@arch-ui/components';

function EmptySearchResults({ query, onClear }) {
  return (
    <Box className="empty-state" style={{ textAlign: 'center', padding: 'var(--spacing-10) var(--spacing-4)' }}>
      <Stack gap="var(--spacing-3)" align="center">
        <Heading level={3} size="display-sm">
          No results found
        </Heading>
        <Paragraph>
          Your search for "{query}" did not match any items.
          Try adjusting your search terms or clearing the filter.
        </Paragraph>
        <Button kind="secondary" onClick={onClear}>
          Clear search
        </Button>
      </Stack>
    </Box>
  );
}
```

Key points:
- Mention the search query so the user knows what was searched.
- Offer a way to clear the search and return to the full list.
- Do not blame the user -- use neutral language like "did not match" instead of "you searched wrong."

## Empty List

When a list or table has no items yet:

```jsx
import { Box, Stack, Heading, Paragraph, Button } from '@arch-ui/components';

function EmptyProjectList({ onCreate }) {
  return (
    <Box className="empty-state" style={{ textAlign: 'center', padding: 'var(--spacing-10) var(--spacing-4)' }}>
      <Stack gap="var(--spacing-3)" align="center">
        <Heading level={3} size="display-sm">
          No projects yet
        </Heading>
        <Paragraph>
          Projects you create will appear here. Get started by
          creating your first project.
        </Paragraph>
        <Button kind="primary" onClick={onCreate}>
          Create project
        </Button>
      </Stack>
    </Box>
  );
}
```

Key points:
- Explain what will appear in this space once it has content.
- Provide the primary action to populate the list.
- Use an encouraging tone -- this is the user's first interaction with this feature.

## First-Time Use

When a user encounters a feature for the first time and needs onboarding:

```jsx
import { Box, Stack, Heading, Paragraph, Button } from '@arch-ui/components';

function WelcomeEmptyState({ onGetStarted }) {
  return (
    <Box className="empty-state" style={{ textAlign: 'center', padding: 'var(--spacing-12) var(--spacing-4)' }}>
      <Stack gap="var(--spacing-4)" align="center">
        <Heading level={2} size="display-md">
          Welcome to your dashboard
        </Heading>
        <Paragraph>
          This is where you will see an overview of your activity,
          recent updates, and quick actions. Complete your profile
          to get personalized recommendations.
        </Paragraph>
        <Button kind="primary" onClick={onGetStarted}>
          Complete your profile
        </Button>
      </Stack>
    </Box>
  );
}
```

Key points:
- Describe what the feature does and what the user will see once it is active.
- Guide the user toward the first meaningful action.
- Keep the tone welcoming rather than instructional.

## Empty State with Illustration

For high-visibility empty states, add an illustration or icon above the heading:

```jsx
import { Box, Stack, Heading, Paragraph, Button } from '@arch-ui/components';

function EmptyNotifications() {
  return (
    <Box className="empty-state" style={{ textAlign: 'center', padding: 'var(--spacing-10) var(--spacing-4)' }}>
      <Stack gap="var(--spacing-4)" align="center">
        {/* Decorative illustration -- aria-hidden since the text conveys meaning */}
        <img
          src="/illustrations/empty-inbox.svg"
          alt=""
          aria-hidden="true"
          width="160"
          height="120"
        />
        <Heading level={3} size="display-sm">
          All caught up
        </Heading>
        <Paragraph>
          You have no new notifications. We will let you know
          when something needs your attention.
        </Paragraph>
      </Stack>
    </Box>
  );
}
```

Mark decorative images with `aria-hidden="true"` and an empty `alt` attribute. The heading and paragraph already convey the message.

## Writing Guidelines

| Do | Do not |
|----|--------|
| "No projects yet" | "Error: 0 projects found" |
| "Try adjusting your search" | "Your search failed" |
| "Get started by creating..." | "Nothing here" |
| Use the feature name in the heading | Use generic "No data" for everything |

## Accessibility Checklist

- Use semantic headings (`Heading` with appropriate `level`) so screen readers can navigate to the empty state.
- Action buttons must be descriptive -- "Create project" rather than "Click here."
- Decorative images use `aria-hidden="true"` and empty `alt=""`.
- If the empty state replaces a list that was previously populated, consider using `aria-live="polite"` on the container so the state change is announced.
