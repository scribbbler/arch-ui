# FormControl

<span class="status-badge status-badge--stable">stable</span>

A context-providing wrapper that connects a label, input, helper text, and error message via ARIA. Exposes a React context so child components (FormLabel, FormHelperText, FormErrorMessage, Input, Textarea, etc.) can co-ordinate their IDs, required state, disabled state, and invalid state without prop-drilling.

## Accessibility

**Notes:**

- FormControl generates a stable id via useId when none is provided; all child components derive their own ids from this root id.
- FormLabel renders a &lt;label&gt; with htmlFor pointing to the root id, creating a native accessible name relationship.
- FormHelperText renders with id='&#123;id&#125;-helper'; inputs should include this in aria-describedby.
- FormErrorMessage renders with id='&#123;id&#125;-error' and role='alert'; only mounts when invalid is true so the alert fires at the right moment.
- aria-required is reflected by the Input when required=true is set on the FormControl.
- aria-invalid is reflected by the Input when invalid=true is set on the FormControl.
- aria-disabled is reflected by the Input when disabled=true is set on the FormControl.

## Usage Guidelines

**Do:**

- Always place FormLabel as a direct or nested child of FormControl so it picks up the correct id.
- Use FormHelperText for persistent guidance and FormErrorMessage for validation feedback — not both with overlapping content.
- Supply a meaningful id prop when server-rendering to avoid hydration mismatches from auto-generated ids.
- Keep FormErrorMessage content concise and actionable.

**Don't:**

- Do not use FormLabel outside a FormControl — it will have no htmlFor target.
- Do not render FormErrorMessage when the form has not yet been submitted or touched, to avoid prematurely alarming users.
- Do not nest FormControl instances — context will be overwritten by the innermost provider.
