# ProgressBar

<span class="status-badge status-badge--stable">stable</span>

A linear progress indicator for operations with a known or unknown completion percentage. Supports a determinate mode (value 0–100) and an indeterminate mode for operations of unknown duration. Fully accessible via ARIA progressbar role.

## Props

| Prop | Type | Default | Description |
|---|---|---|---|
| `value` | `number` | `0` | Current progress value between 0 and 100. Ignored when indeterminate=true. |
| `indeterminate` | `boolean` | `false` | When true, the bar animates continuously to indicate an operation of unknown duration. |
| `size` | `'sm' \| 'md'` | `md` | Height of the progress bar track. sm=4px, md=8px. |
| `label` | `string` | `undefined` | Accessible label applied as aria-label. Always required for screen-reader users. |
| `successValue` | `number` | `100` | Value at which the bar switches to a success state (green fill). Defaults to 100. |
| `showLabel` | `boolean` | `false` | When true, renders a percentage label alongside the progress bar. Hidden for indeterminate mode. |
| `className` | `string` | `undefined` | Additional CSS class names applied to the outermost wrapper element. |
## Accessibility

**Role:** `progressbar`

**ARIA attributes:** `aria-valuenow`, `aria-valuemin`, `aria-valuemax`, `aria-label`

**Notes:**

- role='progressbar' is always present.
- aria-valuemin is always 0 and aria-valuemax is always 100.
- aria-valuenow is set to the value prop when determinate; omitted when indeterminate.
- aria-label must be provided via the label prop to give the progress bar an accessible name.
- When prefers-reduced-motion is set, the indeterminate animation is disabled and the bar shows at 50% width instead.

## Usage Guidelines

**Do:**

- Always provide a label for screen readers.
- Use indeterminate when the operation duration is unknown.
- Clamp the value prop between 0 and 100 before passing it in.

**Don't:**

- Do not pass a value outside 0–100 — results are undefined.
- Do not use a ProgressBar for multi-step flows — use ProgressSteps instead.
- Do not apply inline styles — use the className prop and extend via CSS tokens.
